# ماژول آزمون‌ها و ارزیابی پرسنل

## هدف و محدودیت استفاده

این ماژول برای آموزش، توسعه فردی، مدیریت عملکرد و شناسایی نیازهای آموزشی کارکنان رستوران طراحی شده است. نتیجه‌ها تشخیص پزشکی یا روان‌شناختی نیستند و نباید به‌تنهایی مبنای استخدام، اخراج، ارتقا یا تصمیم تنبیهی باشند.

متن زیر در گزارش‌های فردی و مدیریتی نمایش داده می‌شود:

> این نتیجه برای تحلیل سازمانی، آموزشی و مدیریتی استفاده می‌شود و جایگزین ارزیابی تخصصی، پزشکی یا روان‌شناسی نیست.

DISC و MBTI محتوای سازمانی الهام‌گرفته و غیرکپی دارند. پیش از استفاده تصمیم‌ساز، سؤال‌ها باید با نمونه محلی اعتبارسنجی، از نظر پایایی و سوگیری بررسی، و توسط HR بازبینی شوند.

## معماری و جداول

برای حفظ سازگاری، جدول موجود `hr_assessment_tests` بانک اصلی آزمون‌هاست و جدول موازی `hr_tests` ساخته نشده است. migration افزایشی `database/migrations/2026_06_30_professional_hr_tests.sql` جداول زیر را اضافه می‌کند:

- `hr_test_categories`
- `hr_test_options`
- `hr_test_scoring_rules`
- `hr_test_periods`
- `hr_test_attempts`
- `hr_test_results`
- `hr_test_role_profiles`
- `hr_test_recommendations`
- `hr_test_audit_logs`

جداول موجود ابعاد، سؤال‌ها، تخصیص‌ها و پاسخ‌ها با ستون‌های لازم برای soft delete، سؤال بحرانی، پاسخ الزامی، محدودیت نقش، attempt و نمایش نتیجه تکمیل می‌شوند. هیچ `DROP` یا `TRUNCATE` اجرا نمی‌شود.

## نصب و Seed

1. migrationها را از صفحه «آپدیت سیستم» اجرا کنید.
2. با نقش Admin به «ساخت ارزیابی» بروید.
3. دکمه «همگام‌سازی ۱۴ آزمون حرفه‌ای رستوران» را بزنید.
4. اجرای دوباره seed مجاز است؛ کدهای پایدار با `ON DUPLICATE KEY UPDATE` همگام می‌شوند و داده‌ای حذف نمی‌شود.

فایل seed: `database/seeds/seed_restaurant_hr_tests.php`.

Seed شامل ۱۴ آزمون و ۳۴۷ سؤال است: DISC، MBTI سازمانی غیررسمی، هوش هیجانی، رضایت شغلی، تعهد سازمانی، ریسک فرسودگی، تناسب نقش، کار تیمی، برخورد با مشتری، مدیریت استرس، شناخت منو، استاندارد سرویس، بهداشت و ایمنی و Upsell.

سؤال‌های دانش منو و SOP قالب عملیاتی قابل‌ویرایش دارند. قبل از فعال‌سازی سازمانی، محتوا و گزینه صحیح آن‌ها باید با منوی جاری، recipe card، قیمت POS، آلرژن‌ها و SOP مصوب رستوران تطبیق داده شود.

## گردش کار

- ساخت/ویرایش بانک، ابعاد و سؤال‌ها: `admin/evaluation-builder.php`
- تخصیص و تاریخچه نتایج: `admin/employee-assessments.php`
- اجرای آزمون و نتیجه مجاز پرسنل: `admin/employee-tests.php`
- گزارش مدیریتی و خروجی: `admin/hr-test-report.php`

تخصیص فعلی با ساختار موجود کاربران، فرد، واحد و نقش را به‌طور کامل پشتیبانی می‌کند. ستون‌های شعبه، شیفت و مدیر مستقیم آماده شده‌اند، اما فعال‌سازی رابط آن‌ها منوط به وجود منبع معتبر شعبه/شیفت/مدیر در پروفایل پرسنل است.

## امتیازدهی

- پاسخ‌ها پیش از ثبت نهایی از نظر سؤال‌های الزامی کنترل می‌شوند.
- امتیاز گزینه، reverse scoring و وزن سؤال اعمال می‌شود.
- درصد هر بعد و میانگین کل محاسبه می‌شود.
- DISC با اختلاف کمتر از ۱۰ درصد دو بعد اول، پروفایل ترکیبی می‌دهد.
- MBTI سازمانی از چهار جفت E/I، S/N، T/F و J/P یک کد ترجیحی می‌سازد؛ این کد تیپ قطعی نیست.
- آزمون ریسک فرسودگی سطح‌های «ریسک پایین»، «نیازمند پایش»، «ریسک متوسط» و «ریسک بالا» دارد.
- پاسخ نامناسب به سؤال critical مستقل از امتیاز کل هشدار آموزشی تولید می‌کند.
- پیشنهادهای آموزشی بر اساس بعد و بازه امتیاز از دیتابیس خوانده می‌شوند.

## امنیت و دسترسی

- همه POSTها با CSRF موجود پروژه محافظت می‌شوند.
- اجرای آزمون با assignment متعلق به فرد/واحد/نقش کنترل می‌شود تا IDOR رخ ندهد.
- نتیجه فقط وقتی به پرسنل نشان داده می‌شود که `show_result_to_employee` فعال باشد.
- مدیر فقط گزارش واحد خودش را می‌بیند؛ Admin و Super Admin طبق permission گزارش کامل دارند.
- خطاهای خام در UI نمایش داده نمی‌شوند و رویدادهای مدیریت آزمون در `hr_test_audit_logs` ثبت می‌شوند.
- IP خام ذخیره نمی‌شود؛ فقط hash آن برای audit نگهداری می‌شود.

## خروجی‌ها

- CSV با BOM برای باز شدن صحیح فارسی در Excel
- نمای چاپی مرورگر برای Print / Save as PDF
- نمودار SVG مستقل برای خروجی تصویر

هیچ کتابخانه جدیدی اضافه نشده است.

## اعتبارسنجی و استقرار

پیش از production:

1. migration را روی نسخه پشتیبان staging اجرا کنید و اجرای دوباره را بررسی کنید.
2. seed را دو بار اجرا و تعداد آزمون/سؤال را کنترل کنید.
3. تخصیص فردی و نقشی، ذخیره موقت، ثبت نهایی، retake و پایان مهلت را تست کنید.
4. نتیجه مخفی/نمایان، دسترسی مدیر واحد دیگر و خروجی‌های CSV/SVG/PDF را بررسی کنید.
5. سؤال‌های منو، آلرژن، بهداشت و SOP را با مسئول آموزش و ایمنی تأیید کنید.
6. برای تصمیم‌های مهم HR، پایایی، روایی شغلی، fairness و adverse impact را دوره‌ای پایش کنید.

## Rollback

Rollback کد با برگرداندن فایل‌های PHP ممکن است؛ داده‌های جدید حفظ می‌شوند. به دلیل سیاست عدم تخریب، rollback دیتابیس شامل حذف جدول یا ستون نیست. در صورت نیاز، آزمون‌ها یا تخصیص‌ها را `inactive` کنید و migration را از اجرای بعدی متوقف کنید. حذف فیزیکی فقط با تأیید انسانی و برنامه جداگانه مجاز است.
